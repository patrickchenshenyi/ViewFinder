# 浏览器版 3DGS 查看器 · 使用说明

本地查看高斯泼溅（`.ply` / `.splat` / `.ksplat`）的工具，基于
[GaussianSplats3D](https://github.com/mkkellogg/GaussianSplats3D)（three.js / WebGL2）。
配套的原生应用（Brush）见 `tools/README.md`。

---

## 1. 快速开始

```bash
# 启动（双击也行）
./tools/open-web-viewer.command
# → 浏览器打开 http://127.0.0.1:8099/

# 停止
pkill -f serve-splat-web.mjs
```

默认加载 `tools/splat-web/dist/splats/default.ply`（当前是
`results/phone_720p_smoke/1081_shutdown/.../iteration_1081/point_cloud.ply` 的副本，sha256 一致）。
若同目录存在 `cameras.json`，查看器会**自动切到训练视角**（见第 4 节）。

想看你自己的重建结果，两种方式：

1. **直接把 `.ply` 拖进页面**（最省事，无需复制文件）；
2. 把文件放进 `tools/splat-web/dist/splats/`，然后开
   `http://127.0.0.1:8099/?url=splats/你的文件.ply`。

> 服务只暴露 `dist/` 目录，项目里的 `.env`、训练输出不会发布到本地端口上。

## 2. 界面与操作

| 操作 | 效果 |
|---|---|
| 左键拖拽 | 旋转 |
| 滚轮 | 缩放 |
| 右键拖拽 | 平移 |
| 拖入 `.ply` 文件 | 加载该文件 |
| **H** 键 / 「隐藏面板」 | 收起控制面板（面板会挡住画面主区域，看图时建议收起） |
| ← / → 键 | 切换上/下一个训练视角（需有 cameras.json） |

面板从上到下：文件信息（高斯数、包围盒、当前尺寸参数、训练相机）→ 文件/视角按钮 →
训练视角导航 → **4 个显示质量旋钮**。

## 3. 四个显示旋钮（含实测推荐值）

| 旋钮 | 对应参数 | 默认 | 作用与建议 |
|---|---|---|---|
| **高斯尺寸** | `splatScale` | **1.35x** | 屏幕空间整体缩放所有高斯。等同于 Brush 的 "Splat Scale"。**实时生效**。实测 1.35x 最接近参考渲染；1.0x 明显偏软。 |
| **单个高斯屏幕尺寸上限** | `maxScreenSpaceSplatSize` | **不限** | 单位像素，专治少数超大高斯糊满画面。**训练视角下请保持不限**（开上限会显著降低保真度）；自由视角被糊住时可开到 **128–192**（见第 4 节，注意它只能减轻、不能根治）。 |
| **低不透明度剔除** | `splatAlphaRemovalThreshold` | **1** | 剔除几乎透明的高斯。实测 1→10 差异 <3%，一般不用动。 |
| **抗锯齿 Mip 滤波** | `antialiased` | **关** | 开启会给 2D 协方差加常数核，对小高斯偏柔化。实测关掉后 SSIM 更高、锐度更贴近参考渲染。 |

另外两个**只能通过 URL 参数**调整（UI 未暴露，属诊断用）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `kernel` | 0.3 | 投影后加到屏幕空间协方差的常数。**千万不要设为 0** —— 实测相关度归零（-0.025）、画面几乎全黑，它是投影的数值稳定项。 |
| `focal` | 1.0 | `focalAdjustment`，等效于反向缩放高斯屏幕尺寸。1.0 最优。 |
| `smax` | 0（关） | 按世界坐标（占场景稳健半径百分比）钳制高斯尺度，会改写上传缓冲。当 n% 场景半径用。 |

### 为什么默认是这套值（实测数据）

标尺：`results/phone_720p_smoke/1081_shutdown/image/1081_<id>.jpg` —— Photo-SLAM 自身渲染器
在同一批高斯、同一训练位姿下的输出（PSNR 28–30dB），可作为"正确答案"。

把相机放到训练位姿、视口对齐到 720×1280 后逐像素比较（`tools/_smoke/compare_ref.py`）：

| 配置 | cam0 SSIM | cam2 SSIM | cam15 SSIM | 平均 | 我的锐度 / 参考锐度 |
|---|---|---|---|---|---|
| **1.35x + 关抗锯齿（当前默认）** | **0.9537** | **0.9536** | 0.9507 | **0.9527** | 27.4 / 27.0 |
| 1.35x + 开抗锯齿 | 0.9523 | 0.9522 | 0.9484 | 0.9510 | 22.4 / 27.0 |
| 1.25x + 关抗锯齿 | 0.9480 | 0.9488 | 0.9531 | 0.9500 | 32.2 / 34.5 |
| 1.0x + 开抗锯齿（原始默认） | 0.9052 | — | 0.9302 | — | 32.7 / 27.0 |
| 1.0x + 上限 320px | 0.8264 | — | — | — | 33.0 / 27.0 |
| 1.0x + 上限 64px | 相关度 0.34、PSNR 8.48（严重破坏） | | | | |

结论：**略微放大高斯（1.35x）并关掉 Mip 滤波**，最接近重建器自己的渲染。
注意 PSNR 单指标会偏好更大的尺寸（有"偏好模糊"的偏差），上表以 SSIM 与锐度匹配为准。

## 4. 关键：视角比参数重要得多

用默认的"自动框景"（从重建体外斜后方看）时，画面会糊成一团 —— 整屏被亮雾覆盖，
暗像素 0%。原因不是参数错，而是这份 ply 里有约 178 个**尺度极大的游离高斯**
（全量包围球半径 7.28，1%/99% 分位裁剪后仅 1.36；99 分位屏幕 extent 达 180px），
从外部观察时会叠成一层雾。

从**训练视角**（重建体内部）看，同一批高斯渲染正常且清晰。所以：

- 有 `cameras.json` 时，查看器默认就进入训练视角（第 1 个相机），并按 `fy` 对齐焦长；
- 面板里可用「上一个/下一个训练视角」或 ← / → 键在 57 个相机间切换；
- **这与 Brush 里 "Splat Scale = 1.0x 最接近原场景" 的观察并不矛盾**：Brush 打开时也是从
  数据自身的视角看的，自由视角同样会糊。

| 场景 | 建议参数 |
|---|---|
| 训练视角（默认，重建体内） | 尺寸 1.35x、上限**不限**、抗锯齿关 |
| 自由视角 / 从外部环绕 | 上限开到 **128–192px**；或按 ← → 回到训练视角 |

自由视角实测（当前默认参数下，仅改上限）：

| 上限 | 均值 | 标准差 | 暗像素 | Tenengrad |
|---|---|---|---|---|
| 不限 | 136.5 | 34.6 | **0.0%** | 4.8 |
| 320 | 106.6 | 47.2 | 1.1% | 12.8 |
| 192 | 89.3 | 56.5 | 19.2% | 14.0 |
| 128 | 78.3 | 61.1 | 33.2% | 14.6 |
| 64 | 61.8 | 57.9 | 45.7% | 17.4 |

即上限确实能把"整屏亮雾"压掉、让结构和暗背景回来（见
`tools/screenshots/web-viewer-free-view-cap128.png` 与 `...-cap320.png` 对比），
**但自由视角仍然偏软、基本认不出物体** —— 这是单面采集 + 大量游离高斯的**数据特性**，
不是查看器参数能根治的。要看清场景请用训练视角。

## 5. URL 参数总表

```
http://127.0.0.1:8099/?url=splats/default.ply&kf=0&sscale=1.35&cap=0&aa=0
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `url` | `splats/default.ply` | 加载的场景文件（相对 `dist/`） |
| `cam` | 自动探测 | `cameras.json` 路径；`cam=0` 表示**禁用**训练视角、改用自动框景 |
| `kf` | `0` | 训练相机 id（对应 `1081_<id>.jpg`） |
| `dist` | 1.9 | 自动框景时的相机距离（单位=稳健包围球半径）；仅在无训练视角时生效 |
| `up` | -1 | 世界 Y 轴朝上(`1`)/朝下(`-1`)。画面上下颠倒时切换 |
| `sscale` | 1.35 | 高斯尺寸倍率 |
| `cap` | 0（不限） | 单个高斯屏幕尺寸上限（像素） |
| `smax` | 0（关） | 世界坐标尺寸上限（占稳健半径百分比） |
| `alpha` | 1 | 低不透明度剔除阈值 |
| `aa` | 0 | `aa=1` 开启 Mip 抗锯齿 |
| `focal` | 1.0 | `focalAdjustment` |
| `kernel` | 0.3 | 抗锯齿核常数（勿设 0） |
| `hud` | 1 | `hud=0` 隐藏面板（截图/自动化用） |
| `frames` | 0 | 跑满 N 帧后停住渲染循环（无头截图用） |

## 6. 用训练视角评估重建质量

这是判断"重建好不好"的推荐工作流（自由视角容易高估或低估）：

```bash
# 1. 从训练相机 0 渲染一张，视口与参考图对齐（720x1367 的窗口 → 720x1280 视口）
node tools/verify-web-viewer.mjs \
  --url "http://127.0.0.1:8099/?frames=45&hud=0&cam=splats/cameras.json&kf=0" \
  --out _smoke/check_k0.png --size 720,1367

# 2. 与 Photo-SLAM 自己的渲染逐像素对比（SSIM / PSNR / 相关系数 / 锐度）
3DGS_demo/.venv/bin/python tools/_smoke/compare_ref.py \
  results/phone_720p_smoke/1081_shutdown/image/1081_0.jpg _smoke/check_k0.png
```

参考基准（本数据 1081 迭代、17,846 高斯）：SSIM ≈ 0.95、相关系数 ≈ 0.89、PSNR ≈ 22dB。
如果明显低于这个水平，说明该视角重建质量有问题，而不是查看器设置问题。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 画面糊成一团、发白 | 在自由视角且被游离高斯糊住 → 开「屏幕尺寸上限」到 128–320；或按 ← → 回训练视角 |
| 画面几乎全黑 | 别把 `kernel` 设成 0；确认 `sscale`/`cap` 没被设成极小值（浏览器控制台有 beacon 日志） |
| 上下颠倒 | 点「翻转 Y 轴」，或 `?up=1` |
| 看不到东西 / 相机钻进点云 | 用「重置视角」；无 cameras.json 时用 `?dist=` 调自动框景距离 |
| 端口被占用 | `PORT=8100 ./tools/open-web-viewer.command` |
| 改了代码没生效 | 服务只做静态分发，刷新页面即可；`app.js`/`index.html` 无缓存（`Cache-Control: no-cache`） |

## 8. 已知限制

- 自由视角（`cam=0`）对这类含大量游离高斯的单目重建结果观感较差，这是数据特性，非查看器缺陷。
- 面板目前不可拖动，挡住画面时按 **H** 隐藏。
- 一次只加载一个场景；切换场景会重新上传几何（约 1 秒）。
- 训练视角下相机会被锁到该位姿；再次拖拽即进入自由视角（此时可开上限）。
- 训练视角模式下「翻转 Y 轴」按钮**无效果**（朝向完全由 `cameras.json` 的位姿决定），要翻转换到自由视角用。
- `.splat` / `.ksplat` 不支持尺寸改写类操作（`smax`），但 `sscale` / `cap` 正常。

## 9. 实现注记（改代码前先看）

- **单位**：`maxScreenSpaceSplatSize` 是**像素**（着色器里 `basisViewport = 1/viewport` 负责换算到 NDC）。
  曾误按 clip space 用 `2N/宽度` 换算，把 96px 变成 0.15 传进去 → 所有高斯被钳到 0.15px，画面全黑。
- **着色器尺寸公式**：`basis = eigenVector * splatScale * min(√8·√λ, maxScreenSpaceSplatSize)`，
  即上限作用在 `splatScale` **之前**，两个旋钮可独立组合。
- **取景**：默认用 1%/99% 分位裁剪后的"稳健包围盒"，否则游离高斯会把相机推远 5 倍。
- **焦长对齐**：`camera.fov = 2·atan((视口高/2)/fy)`，因为 GS3D 每帧按
  `focal = (渲染高/2)/tan(fov/2)` 计算，这样渲染焦长（像素）恰等于训练时的 `fy`。
- **训练相机坐标约定**：`cameras.json` 的 `position` 是相机中心、`rotation` 为 3×3（相机→世界）；
  COLMAP 相机系为 +X 右 / +Y 下 / +Z 前，故视线 = `R·(0,0,1)`、世界上方 = `-R·(0,1,0)`。
- **验证工具**：`tools/verify-web-viewer.mjs` 用 CDP 驱动无头 Chrome，断言 `window.__viewfinder.ready`
  并截图；无头 Chrome 必须带 `--no-sandbox`，崩溃转储目录已重定向到项目内。
  支持 `--size`（对齐视口，如 `--size 720,1367` → 视口 720×1280）、`--js`（就绪后执行 JS，
  用来测按钮/交互）、`--after`（执行后等待毫秒）。
- **坑：GS3D 的 `Viewer.dispose()` 是异步的**，其收尾逻辑会执行
  `document.body.removeChild(rootElement)`。因此**不能复用同一个容器 div** ——
  否则"重置视角/切训练视角/动滑块"后，新查看器的 canvas 会被旧实例的异步收尾连容器一起摘掉，
  表现为**整屏变黑且 canvas 变成 0×0**。正确做法是每个查看器实例用独立的宿主 div
  （见 `app.js` 的 `newViewerHost()`）。这个 bug 只在"页内重渲染"时出现，
  新开页面的测试**测不到**，必须用 `--js` 点击按钮才暴露。
- **测量注意**：不要用"裁剪矩形"排除 HUD 来算指标 —— 面板上文字/滑块的梯度能量极高
  （曾把 Tenengrad 从 8.3 抬到 40.6，导致整轮结论错误）。用 `?hud=0` 截图，或用遮罩。

## 10. 模型切换与下载（M6.0c 里程碑）

面板新增「原始模型（M0→M5） / M6.0c 模型」两个切换按钮与两个下载链接：

| 文件 | 内容 |
|---|---|
| `splats/m5_original.ply` | M0→M5 最终重建（102,749 高斯，25.5MB） |
| `splats/m6_processed.ply` | M6.0c 处理模型（**除雾版**：原始 102,749 → 几何 prune −35 → 屏幕空间除雾 −122 → 102,592 高斯） |
| `splats/m5_cameras.json` | 两模型共用的训练相机（180 个；注意与旧的 `splats/cameras.json` 是不同 id 空间，勿混用） |

- 切换「M6.0c 模型」时前端先 **HEAD 探测**文件是否存在：**不存在则提示「尚未完成（构建中）」**，构建完成后**无需刷新**即可切换（每次点击重新探测）；
- 对应下载链接在模型缺失时置灰（`a.dlink.disabled`）；
- 服务端 `serve-splat-web.mjs` 已支持 `HEAD`（只回状态不传 body，供存在性探测）；
- 无头验证 PASS：点击切换后 `name=m6_processed.ply`、`count=102592`、训练视角 1/180。

## 11. 帮我构图（M6.4 端到端入口）

面板「🖼 帮我构图」按钮展示当前端到端结果：点击后弹出 **Top-3 构图建议**（3 张效果图 + VLM 点评）。

| 文件 | 内容 |
|---|---|
| `framing/framing.json` | top-3（候选名 + 位姿 R/C + 点评），由 `m6/vlm_score.py` 产出 |
| `framing/<name>.png` | 3 张效果图（1280×720 渲染，基于 M6.0c 除雾模型） |

- 点评由 `deepseek-v4-flash-vision-exp` 生成（场景感知，如"机箱与显示器分居左右…"）；
- 点按钮 → fetch `framing/framing.json` → 弹窗展示；点「✕ 关闭」或点遮罩关闭；
- 无头验证 PASS：点按钮后 `#framingList` 有 3 条、面板 `.on`。
